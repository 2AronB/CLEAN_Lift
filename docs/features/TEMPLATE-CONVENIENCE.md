# Template convenience and previous values

Ownership: ui/TemplatesScreen.kt (Duplicate workout), data/ProgressDao.kt + data/PreviousWorkoutValues.kt (prior-value projection), ui/WorkoutViewModel.kt + ui/WorkoutScreen.kt (reference loading and explicit copy). No schema change beyond the separate measurement migration.

Duplication creates an unsaved builder draft with a new name and no template ID. Saving inserts a new template; cancelling cannot change the original. Duplicate-name conflicts keep the draft open. Existing ordered exercise/fixed-count/Until done configuration is retained. The current draft is copied, including deliberate unsaved edits; it does not modify the source template.

Previous values come from the latest completed workout containing saved sets for the exercise by start time/ID. The compact reference uses its last occurrence/set by stored position. An expandable list below the save controls shows every set in exercise-position/set-position order, including repeated occurrences with original workout exercise/set positions. Compare stable exercise IDs, so catalog renames do not lose references. Never use another exercise or an active workout as the source. Show the original unit, exact thousandths, reps and date. Use previous workout values or Copy set copies into the new-set form; Save set is still required. If a changed draft would be overwritten, show discard protection. Copy is unavailable while editing an existing set. Current workout previous-set defaults continue to win automatically; cross-workout values require an explicit copy. A reference is not a prescribed starting load or automatic progression.

Tests: ProgressDataTest checks latest completed source, original unit/precision/date, stable IDs through renames, no-data behavior and active exclusion. Existing template repository tests cover distinct records, ordered plans, validation and snapshot isolation. Duplication and draft-copy/discard interactions remain manual.

Future additions should preserve these boundaries: generation previews may offer reference values with provenance; saving a template must not rewrite active/history snapshots. Consider create-template-from-history and named rep-range goals as separate small slices.
