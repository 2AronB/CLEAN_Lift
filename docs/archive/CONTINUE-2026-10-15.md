## Important limitations

- Break loss is a default-zero user scenario, not expected personal detraining or prescribed load.
- Chart records are all-time; range filters affect chart/list only. Body dates are plain days, workout dates are start timestamps.
- Measurement metrics are predefined, including left/right; one entry per metric/day. No custom measurements or measurement notes yet.
- Calculated health metrics are explicit saved input snapshots; editing an original body measurement does not silently rewrite a saved BMI/body-fat result. Correct that result deliberately. Historical profile age is not inferred. Health records permit multiple entries per method/day. Reference scope/method is shown; no universal athletic score is invented. Legacy body-measurement technique is unknown.
- Relative strength requires same-day bodyweight; no stale/future weight is substituted. Big 3 mappings require explicit distinct exercise IDs; single and estimated session totals differ from separate personal-best sums. No automatic competition judging or cross-equipment load normalization.
- Equipment-based strength generation is implemented. No adaptive overload, timed HIIT sets, rest timer, supersets, RPE/notes editor or export/import yet. Equipment choices do not yet store actual available weight ranges/increments or machine identity; no numeric weight prescription is generated.
- SQLite name search uses lower()/instr() and is literal (not wildcard expansion); full Unicode case folding of snapshot names is a future refinement.
- No automated UI tests or performance profiling; manual checks remain pending. Do not mark them accepted without a user report.
