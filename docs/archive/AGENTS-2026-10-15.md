# Product Philosophy

This app should feel like a polished stock Android utility.

Core principles:

- fully functional offline
- no advertisements
- no subscriptions
- no accounts
- no analytics
- no telemetry
- no tracking
- no cloud backend
- no unnecessary permissions
- no `INTERNET` permission
- user data stays on the device
- simple, fast, reliable UI
- Material 3 design
- light and dark themes
- minimal dependencies
- avoid feature bloat

Do not add SDKs, libraries, permissions, services, or network functionality unless they are clearly necessary and I approve them first.

# Initial Product Scope

The first version is a basic strength-training workout logger.

The user should eventually be able to:

## Exercises
- view exercises
- create custom exercises
- edit exercises
- categorize exercises if useful

## Workout Templates
- create reusable workout templates
- add exercises to a template
- reorder exercises
- specify intended sets or rep ranges

## Active Workout
- start from a template
- start an empty workout
- enter sets
- record:
  - weight
  - reps
  - optional RPE
  - optional notes
- quickly copy or reference the previous workout's values
- add/remove sets
- add/remove exercises
- finish or cancel a workout

## History
- view previous workouts
- inspect exercises and sets from a previous workout
- edit obvious logging mistakes where practical

## Progress
Initially keep this simple.

Support basic personal records such as:
- highest weight
- highest estimated 1RM
- best performance for common rep counts if straightforward

Do not build advanced analytics until the basic logger is excellent.

## Rest Timer
Eventually support a basic rest timer.

Do not make timer implementation the first priority.

# Data Safety

Workout history is important user data.

Design the local data model carefully.

Avoid database migrations or schema changes that could silently destroy existing data.

When schema changes become necessary:
- explain the migration
- preserve existing data
- add tests where practical

Eventually we will implement explicit backup/export and Android-supported backup behavior.

---

# Security and Privacy

The app should not contain:

- `android.permission.INTERNET`
- advertising SDKs
- analytics SDKs
- telemetry SDKs
- crash-reporting services that transmit data
- account authentication
- embedded web content

External website links may eventually open in the user's normal browser using Android intents. This does not justify adding Internet permission to the app itself.

If any dependency attempts to introduce networking, tracking, or unnecessary permissions, flag it.

# UI Philosophy

The app should resemble a high-quality native Android utility, not a startup website.

Prefer:

- Material 3 components
- standard Android interactions
- clear typography
- high information density where useful
- obvious tap targets
- minimal decorative clutter
- restrained animation
- sensible back-button behavior

- accessibility support
- dark mode

- excessive cards
- gradients for decoration
- unnecessary onboarding
- engagement gimmicks
- streak pressure
- social features

- upsell-style UI
